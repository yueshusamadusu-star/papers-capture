# 0.3.0 截图问题与全文收集验收

日期：2026-10-13（北京时间）。BASE_SHA：`f0a5c413c9d00519b275da9dc9d965a06d8848e4`。代码RESULT_SHA以包含本记录的Git提交为准。本版不是校园订阅全文自动抓取验收。

## 作者指出的实际差距

0.2.0的 `search --open` 只生成链接清单，不执行下载；collect只支持少数域且未配置Unpaywall邮箱时返回人工入口。作者访问SciTePress个人账号页与ScienceDirect学校识别页，仍没有自动取得全文，这与自动收集的预期不符。测试通过只覆盖当时功能，不能用来声称已满足整个预期。

本机仅核对UNPAYWALL_EMAIL是否存在有效联系邮箱，结果为false；不读取/记录学校口令、Cookie或API密钥。未配置邮箱导致开放版本查询尚未执行，应如实区分“未查”与“没有”。

## 修正行为

- 新增CLI `search --collect` 与MCP `search_and_collect`，检索后串行尝试全文，HTML/JSON逐篇记录状态；已保存条目链接本地PDF。纯检索清单明确标注未收集。
- SciTePress仅对支持的16位数字DOI，根据Crossref同DOI、出版年与官方资源域构造公开PDF路径约定。实际HTTP/PDF检查成功后才记保存；来源JSON说明路径约定，不伪装成页面明确给出了PDF元数据。
- Unpaywall检查当前多个oa_locations，支持的其他位置可替代不可用最佳位置；不使用尚在禁运中的位置。无邮箱也核对Crossref公开元数据；匹配已生效CC许可、同内容版本与支持域的已声明PDF可保存，不把TDM许可等同OA。
- 每篇最多3个候选；404/410、401/403或非PDF可检查其他公开位置。429停止整个队列并保存已完成结果，不换来源规避限流。重复DOI不再次收集，原文件不覆盖。
- 用户报告 `--access-state not_subscribed` 时仍先尝试公开来源，失败后给同DOI查找与浙大文献传递，不再弹相同机构登录页。状态明确为用户报告，未独立确认学校采购。

### ScienceDirect：未取得全文，退避状态已验证

完整输出、PDF、清单和来源JSON仅在忽略的verification-local/v0_3，均不提交公开仓库。真实联网脚本可以在新的未存在目录复查，不为文档修订重复下载样例。
